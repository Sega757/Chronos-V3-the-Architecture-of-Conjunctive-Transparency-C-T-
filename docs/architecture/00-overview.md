# SCCS / Chronos V3 — Architecture Overview

The **Sovereign Self-Correcting Cognitive System (SCCS)** is a bicameral
reasoning architecture built around one governing principle:

> No claim crosses a trust boundary unaccompanied by the evidence and
> cryptographic provenance needed to independently re-verify it.

We call that principle **Conjunctive Transparency (C-T)** — see
[`02-conjunctive-transparency.md`](02-conjunctive-transparency.md). Every
other design decision in this repository exists to make C-T enforceable in
code, not just asserted in prose.

## The three subsystems

| Subsystem | Codename | Role | Service in this repo |
|---|---|---|---|
| **System 1** | Neocortex | Fast, associative, stochastic hypothesis generation. Cheap, high-recall, low-precision. | [`services/system1_hypothesis_generator`](../../services/system1_hypothesis_generator) |
| **System 2** | Chronos Engine / Thought Layer | Slow, deterministic ground-truth verification. Expensive, high-precision. The only subsystem allowed to call a candidate "grounded." | [`services/system2_chronos_verifier`](../../services/system2_chronos_verifier) |
| **System 0** | Meta-Arbiter | Governance and dispute resolution. Resolves the cases System 2 cannot decide alone, via Proof-of-Sampling consensus among staked arbiter nodes. | [`services/arbiter_module`](../../services/arbiter_module) |

Full detail on how these three interact: [`01-bicameral-architecture.md`](01-bicameral-architecture.md).

## Repository map

```
proto/                          gRPC service contracts (source of truth for the wire format)
  common.proto                  shared types: EpistemicState, Provenance, Signature, ContentHash
  system1_hypothesis.proto      HypothesisGenerator service (System 1)
  system2_verifier.proto        ChronosVerifier service (System 2)
  arbiter.proto                 MetaArbiter service (System 0) + L-E-J-D-A-S governance types

db/migrations/                  PostgreSQL schema, applied in order
  001_init.sql                  nodes, hypotheses, verifications, audit_log
  002_governance_schema.sql     governance_actions, sanctions (L-E-J-D-A-S)
  003_posp_consensus.sql        arbiter_stakes, consensus_rounds, consensus_samples

libs/chronos_common/            shared Python primitives, imported by all three services
  chronos_common/canonical_json.py   RFC 8785 (JCS) canonicalization
  chronos_common/merkle.py           SHA-256 Merkle trees + inclusion proofs
  chronos_common/signing.py          Ed25519 sign/verify over canonical JSON
  chronos_common/epistemics.py       Shannon entropy, von Mises-Fisher kappa, FOR/FOE/FOC
  generated/                         gRPC stubs (generated by `make proto`, not committed)

services/
  system1_hypothesis_generator/   System 1 reference implementation
  system2_chronos_verifier/       System 2 reference implementation, incl. the zero-hallucination lock
  arbiter_module/                 System 0 reference implementation: PoSP consensus + governance

docker-compose.yml               local multi-service stack (Postgres, Redis, the three gRPC services)
Makefile                         `make proto`, `make test`, `make up` / `make down`
```
